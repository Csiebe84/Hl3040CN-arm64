## Task A — nativer Treiber: FERTIG

Der Druckpfad ist reines Python, **kein qemu**:

- `/usr/lib/cups/filter/brhl3040cn-filter` = 283-B-Bash-Wrapper
  → `exec /usr/local/lib/brhl3040cn/.venv/bin/python3
  /usr/local/lib/brhl3040cn/brhl3040cn-filter.py "$@"`
- PPD: `*cupsFilter: "application/vnd.cups-postscript 0 brhl3040cn-filter"`
- Beide Queues (`Brother_HL-3040CN`, `HL3040_TEST`) nutzen diesen Filter.

**Beweis (heute nachgemessen, reproduzierbar):** Derselbe PS-Input durch
nativen Filter und durch den Oracle (Docker `brother-cups`, i386) ergibt eine
**byte-identische XL2HB-Nutzlast**:

```
/tmp/blk_native.prn : 79716 B gesamt, XL2HB-Marker @213, Nutzlast 79503 B
/tmp/blk_oracle.prn : 79503 B gesamt, XL2HB-Marker @0,   Nutzlast 79503 B
Nutzlast identisch: True (79503 vs 79503)
```

Der native Filter stellt zusätzlich einen PJL-Kopf voran
(`@PJL SET ECONOMODE/RENDERMODE/...` + `@PJL ENTER LANGUAGE=XL2HB`) und
schließt mit `@PJL EOJ`. Der Oracle schreibt ein `@PJL JOB NAME="Print Job"`
am Anfang — der native Filter **nicht**. Das ist der einzige Unterschied im
Rahmen; die Rasterdaten sind gleich. *Falls je ein Druckproblem auftaucht,
ist das der erste Ort zum Nachsehen.*

**Wichtig:** Nicht erneut den byte-Vergleich aufsetzen — er ist erledigt.

## Task D — Android: Server-Seite FERTIG, Gerätetest offen

**Ursache (gefunden):** CUPS lauschte nur auf `localhost:631`, und
`<Location />` war deny-all. Ein Android-Gerät im LAN kam damit nicht rein.

**Fix (angewendet, Backup vorhanden):**

```
Backup: /root/backup-cups-android-20261025-231538.conf
/etc/cups/cupsd.conf:
  -  Listen localhost:631        +  Listen 0.0.0.0:631
  +  Listen [::]:631                (Android bevorzugt IPv6, RFC 6724!)
  +  <Location />:  Allow @LOCAL    (nur das Web-Interface; /admin bleibt
                                     separat gesperrt - unveraendert)
```

**Verifiziert (heute):**
- `ss -ltn` → lauscht auf `0.0.0.0:631` **und** `[::]:631`
- `curl http://192.168.178.71:631/` → **HTTP 200** (vorher nur localhost)
- `ipptool` gegen `ipp://127.0.0.1:631/printers/Brother_HL-3040CN` → **PASS**
- Queue unterstützt **`application/pdf`, `image/urf`, `image/pwg-raster`,
  `image/jpeg`, `application/postscript`** → alles, was Android/Mopria braucht
- mDNS: der Odroid advertiert jetzt (`SRV port=631 target=odroidn2`)
- Firewall: 631 ist für `192.168.178.0/24` **und** das globale IPv6-/64 offen
  (`/etc/default/fw-rules`, `LAN_TCP_PORTS` enthält 631)

**Noch offen (braucht das echte Handy):**
1. Am Android-Gerät: Einstellungen → Drucken → "Standard-Druckerdienst" →
   nach Druckern suchen. Erwartet: `Brother_HL-3040CN @ odroidn2`.
   Falls nicht: manuell hinzufügen über `ipp://192.168.178.71:631/printers/Brother_HL-3040CN`.
2. **Achtung IPv6:** Das Handy kommt evtl. über IPv6. Deshalb steht `[::]:631`
   in der Config. Wenn es hakt: prüfen, ob die FRITZ!Box IPv6 zum Odroid
   durchlässt (`ALLOW_GLOBAL_IPV6=1` ist gesetzt).
3. **Achtung zweite LAN-IP:** Der Odroid hat `.71` (WLAN) und `.4` (Ethernet).
   `server_name`/SAN deckt beide ab. Nicht wundern.

**Nicht verwechseln:** Der *Drucker* (`.50`) spricht **kein echtes IPP**
(`/ipp/print` → 404; er advertiert nur `pdl=application/vnd.brother-hbp`).
Deshalb geht der Weg über den Odroid als IPP-Server, nicht direkt zum Drucker.

## Fallen (wiederkehrend, teuer)

- **Agent-Server-Port ist 8000**, nicht 8001. Kein API-Key nötig.
- **Events-API: `limit=100`** benutzen; `limit=200` gibt **HTTP 422**.
- **Nicht `POST /events` an eine laufende Conversation** — hängt 20 s.
- **`docker exec` auf den Oracle** nur, wenn wirklich ein Vergleich nötig ist;
  er ist der Emulator, den Task C abbauen soll.
- **RAM ist knapp** (3,7 GB, zeitweise <100 MB frei). Keine `make -j2`-Builds,
  keine mehreren Browser parallel. Firefox-Headless hinterlässt Zombies
  (`pkill -f "firefox.*headless"`).
- **Eigene Conversation-ID:** steht in `$TMUX` als Session-UUID; der
  Event-Ordner ist `workspace/conversations/<uuid-ohne-bindestriche>/`.
- **Beim Prüfen des Druckers:** rohe PJL-Sonden an `:9100` sind harmlos, aber
  unnötig oft machen. `lpstat -p` reicht meistens.
- **git-Arbeitsbaum ist schmutzig** (viele untracked `tools/`, `hl3040cn/build/`,
  `_*.so`, `logs/`, `ref/`). Vor `git add -A` genau hinsehen.
